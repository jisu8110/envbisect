# EnvBisect

### Find the condition that makes your software fail.

**AI가 제안한 가설을 실제 실험으로 확인하고, 검증된 실패 조건과 통과한 변경을 돌려주는 디버깅 도구.**

## 어제 통과한 CI가 오늘 실패했습니다

런타임을 업데이트한 뒤, 같은 코드와 테스트가 실패합니다.
AI에게 로그를 주면 “런타임 회귀인 것 같다”는 설명을 얻을 수 있습니다.

하지만 개발자가 내려야 할 결정은 그다음입니다.

**버전을 되돌려야 할까? 옵션 하나로 피할 수 있을까? 어떤 입력에서만 실패할까?**

누군가는 이전 환경을 만들고, 조건을 하나씩 바꾸고, 다시 실행해야 합니다.
EnvBisect는 가설과 의사결정 사이에 남아 있는 이 확인 작업을 위해 만들었습니다.

> A hypothesis tells you what might be wrong.  
> An experiment shows which conditions actually matter.

## 설명에서 멈추지 않고, 다음 실험을 실행합니다

EnvBisect는 알려진 정상·실패 조건을 다시 실행하는 것부터 시작합니다.
그 결과를 읽은 AI가 다음에 비교할 조건을 선택하면, Daytona가 조건별 독립 환경을 만들고 실행합니다.

**실행 결과는 보고서로 끝나지 않습니다. 다음 실험을 선택하는 근거가 됩니다.**

```text
정상·실패 조건 재현
        ↓
AI가 다음 비교 선택
        ↓
Daytona가 독립 환경에서 실행
        ↓
결과 비교 → 새로운 증거로 다음 실험 선택 ↺
        ↓
검증된 실패 조건 + 통과한 변경 + 재현 가능한 실행 기록
```

AI는 무엇을 시험할지 고릅니다.
엔진은 허용된 조건과 검증 기준을 지키고, **PASS와 FAIL은 실제 실행이 결정합니다.**

## 데모에서는 무엇을 보나요?

준비된 Node.js 이슈에서 출발합니다.
기대 동작은 바이트 데이터를 숫자 배열로 바라보는 작업이 예외 없이 끝나는 것입니다.
같은 코드·입력·옵션에서 정상 버전과 실패 버전을 먼저 비교합니다.

그다음 질문은 “새 버전이 문제인가?”에서 한 걸음 더 들어갑니다.

- **길이를 명시하면?** 같은 실패 런타임에서도 테스트가 통과하는지 확인합니다.
- **할당 방식이나 배열 너비를 바꾸면?** 결과에 영향을 주는 조건을 분리합니다.
- **입력 크기만 바꾸면?** 실패와 통과가 갈리는 구간을 조사합니다.

숫자 축 탐색이 선택되면 엔진이 후보를 만들고, 새 실행으로 구간을 좁히고 반복 확인합니다.
발표 모드에서는 이 과정을 **문제 → 재현 → 비교 → 증거에 따른 다음 결정 → 결과** 순서로 볼 수 있습니다.

핵심은 많은 테스트를 돌렸다는 것이 아닙니다.
**방금 얻은 증거가 다음에 무엇을 실행할지 바꾼다는 것입니다.**

## 개발자가 가져가는 것은 실행 증거입니다

EnvBisect는 “아마 이것 때문”이라는 설명 대신, 다음 질문에 답할 수 있는 **Evidence Package**를 남깁니다.

| 개발자의 질문 | 제공하는 증거 |
|---|---|
| 어떤 조건에서 실패했나? | 런타임·입력·옵션과 실제 실패 결과 |
| 무엇을 바꾸면 통과했나? | 변경한 조건과 그대로 유지한 조건의 대조 |
| 결과를 믿고 다시 확인할 수 있나? | 실행 명령·원시 관찰·반복 검증·실행 환경의 출처 |
| 다음 담당자에게 무엇을 넘기나? | 다운로드 가능한 실험 이력과 재현 정보 |

이 증거를 바탕으로 롤백이나 우회책을 검토하고, 수정 후보를 확인하거나 다른 개발자·coding agent에게 조사를 넘길 수 있습니다.

결과의 단위는 **verified failure condition**입니다.
재현 테스트의 통과를 앱 전체의 수정 완료로 대신하지 않습니다.

## 왜 Daytona인가?

AI가 “이 조건으로 확인하자”고 선택할 때마다 실제로 실행할 환경이 필요합니다.

Daytona는 EnvBisect 안에서 **조건 하나를 독립된 실행 환경으로 바꾸는 역할**을 합니다.
애플리케이션이 API로 환경을 생성하고, 여러 비교를 병렬 실행하고, 증거를 수집한 뒤 삭제합니다.
화면에는 각 world의 생성·실행·증거 수집·정리 이력이 남습니다.

덕분에 반복적인 환경 준비와 정리를 직접 조합하는 부담을 줄이고,
**어떤 실험을 선택하며 그 결과로 무엇을 결정할지**에 집중할 수 있습니다.

CI도 동적 매트릭스를 만들 수 있고 coding agent도 실험할 수 있습니다.
EnvBisect가 제공하는 것은 이 기능들을 **증거 기반 선택·통제된 비교·재검증·기록 보존의 한 흐름**으로 묶은 조사 경험입니다.

> The LLM chooses the experiment.  
> Daytona creates the worlds.  
> Execution decides what's true.
